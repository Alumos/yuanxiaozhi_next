## 一、三个环节，一个系统

三个环节在同一个 Docker 项目里，共用一个端口，按路径区分：

| 路径 | 环节 | 课上的活动 | 状态 |
|---|---|---|---|
| `/shuru/` | 输入 | 活动一：元小智和学生对话 | **待定**，只预留接口和公共组件 |
| `/jisuan/` | 计算 | 活动二：智能图书管理员。学生连选 5 轮书，每轮 5 选 1，元小智“倒带”分析阅读偏好，推荐 3 本书并标出感兴趣程度 | 规格完成 |
| `/shuchu/` | 输出 | 活动三：消防疏散路线图。元小智在校园平面图（原 HTML）上画出逃生路线 | 规格完成 |

每个环节都有两个页面：

- 学生平板页：`/<环节>/`
- 教室大屏页：`/<环节>/screen`

另外还有两个公共页面：

- `/`：三环节入口，显示各环节的二维码；
- `/admin`：教师控制台，可以切换运行模式、查看模型状态和缓存命中率、重置课堂。

三个环节的界面风格保持一致（见 `公共/02_界面风格规范.md`）。每个环节只是主色不同：输入用蓝色，计算用紫色，输出用绿色。

## 三、开发顺序

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| D0 验证 | 网关的思考程度参数、上下文缓存是否生效（`公共/03` 第 7 节）；平板性能 | 验证记录 |
| D1 骨架 | Docker、路由、公共组件、SSE、状态快照、`/admin`、模型网关、排队、模拟模式 | 三个路径都能打开；模拟模式能对话 |
| D2 图书数据 | **v0.1 已完成 301 本**（`计算/书库/`），待教师审核后定稿 | 书库自检报告 |
| D3 计算环节 | 出题、偏好计算、推荐调用、思考动画、大屏投屏回放 | 25 台平板同时走完 5 轮并拿到推荐 |
| D4 输出环节 | 道路网扩充、规划器、画图说明书 → SVG、核验、发布会 | 6 个组拿到路线图并通过验收 |
| D5 输入环节 | 等需求定下来再排 | — |
| D6 彩排 | 两遍完整彩排；录制回放包；低性能平板实测 | 可上课 |

计算环节的数据（D2）最花时间，可以和 D1 同时进行。

## 四、全局约定

- 文档、提示词、内容数据都用 UTF-8；内容数据放在 `content/`，改内容不用改代码。
- **密钥只从环境变量读取**，不写进任何项目文件；仓库里只有 `.env.example`。
- 不收集学生真实姓名，学生只选座位号或平板号。
- 平板上不发送超过 300 KB 的图片；动画只用 `transform` 和 `opacity`，复杂画面放在大屏。
- 所有大模型调用都在服务端进行，前端拿不到密钥，也拿不到提示词原文。
