# 公共 01 · 总体架构与部署

> 适用于三个环节：`/shuru` `/jisuan` `/shuchu`。

---

## 1. 使用环境

| 项目 | 规格 |
|---|---|
| 学生平板 | 约 30 台（系统按 36 个座位预留余量），2 人一台。按“性能一般的安卓平板 / 旧 iPad”设计，横屏 1280×800 为基准 |
| 教室大屏 | 1920×1080，电脑浏览器全屏打开 `/<环节>/screen` |
| 服务器 | 教室里的一台电脑（Windows / macOS），装 Docker Desktop；不能装 Docker 时，直接运行同一份单文件程序 |
| 网络 | 同一个 Wi-Fi。服务器要能访问外网的模型网关；平板只需要能访问服务器 |
| 协议 | HTTP 即可。实时推送用 SSE，不用 WebSocket |

## 2. 总体结构

```
学生平板 /jisuan/  /shuchu/  /shuru/ ─┐
教室大屏 /<环节>/screen ────────────────┼─ HTTP + SSE ─ 容器 yxz（一个端口 8080）─┬─ 模型网关（OpenAI 协议，流式）
教师控制台 /admin ──────────────────────┘                                      ├─ content/（只读：书库、地图、提示词）
                                                                               └─ /data（读写：状态快照、日志、回放包）
```

- **一个容器、一个进程、一个端口**。三个环节是同一个 Go 程序里的三个模块，共用：
  - HTTP 服务；
  - SSE 推送；
  - 状态快照；
  - 模型网关和排队；
  - 运行模式和日志。
- 前端是一个 Vite 多页面工程。三个环节共用 `src/common/` 里的样式和组件，构建后由 Go 程序用 `go:embed` 打进同一个可执行文件。

## 3. 技术选型

| 层 | 选型 | 理由 / 来源 |
|---|---|---|
| 服务器 | Go 1.25，标准库 `net/http` | 沿用旧平台；单文件，好部署 |
| 前端 | Vue 3 + Vite + TypeScript，多页面 | 沿用旧平台 |
| 实时推送 | SSE（`text/event-stream`），客户端断线自动重连；重连时用 `Last-Event-ID` 补齐 | 只需服务器往下推，学生操作走普通 POST；比 WebSocket 简单，HTTP/1.1 下也稳 |
| 状态 | 内存 + 每 5 秒、以及每次关键操作后写一次 `/data/state/<环节>.json` | 服务器重启后课堂进度可以恢复 |
| 大屏画面 | Canvas 2D（大量小元素，如 300 本书的书库墙）+ SVG（地图、路线）+ CSS | 大屏电脑性能够，平板上不用 Canvas 动画 |
| 容器 | 多阶段构建，最终镜像基于 `alpine` | 镜像小，Windows 和 macOS 的 Docker Desktop 都能跑 |

## 4. 路由

| 路径 | 内容 | 权限 |
|---|---|---|
| `/` | 三环节入口：三个大按钮和各自的二维码 | 公开 |
| `/jisuan/` | 计算环节 · 学生平板 | 公开 |
| `/jisuan/screen` | 计算环节 · 大屏 | 教师口令 |
| `/shuchu/`、`/shuchu/screen` | 输出环节 | 同上 |
| `/shuru/`、`/shuru/screen` | 输入环节（暂为占位页） | 同上 |
| `/admin` | 教师控制台 | 教师口令 |
| `/api/common/*` | 健康检查、加入、配置、口令登录 | 按接口 |
| `/api/jisuan/*`、`/api/shuchu/*`、`/api/shuru/*` | 各环节接口 | 按接口 |
| `/events/<环节>?role=student\|screen` | SSE 推送 | 学生凭座位令牌，大屏凭教师口令 |
| `/assets/*` | 构建产物，文件名带内容哈希，长期缓存 | 公开 |

- 页面 HTML 不缓存（`Cache-Control: no-cache`），`/assets/*` 长期缓存。这样改版后平板刷新一次就是新版本。
- **教师口令**：环境变量 `YXZ_TEACHER_PIN`。输入一次后写进 Cookie，12 小时有效。学生打不开大屏和控制台。

## 5. 身份与座位

- 学生打开任一环节，先选**座位号**（1–36，对应平板号，6 个组每组 6 个座位；在 `content/common/seats.json` 里配置，可以带小组号）。不输入姓名。
- 选好后服务器发一个座位令牌，存在 `localStorage` 和 Cookie 里。同一台平板刷新或换环节都不用重新选。
- 同一个座位号被另一台平板占用时，提示“这个座位已经有平板了，要换到这台吗？”，确认后旧平板显示“已在别的平板上继续”。
- 教师可以在 `/admin` 里清空所有座位。

## 6. 服务器代码结构

```
app/
├─ Dockerfile
├─ docker-compose.yml
├─ .env.example                 只有变量名，没有值
├─ Makefile                     build / run / check / test
├─ server/
│  ├─ cmd/yxz/main.go           入口：serve / check / purge / warmup 子命令
│  └─ internal/
│     ├─ core/                  HTTP 路由、静态资源、教师口令、座位、SSE 中心、状态快照、敏感词与个人信息检测
│     ├─ llm/                   模型网关、思考程度、排队、缓存统计、兜底、回放、模拟
│     ├─ jisuan/                计算环节：书库、出题、偏好计算、推荐、轨迹
│     ├─ shuchu/                输出环节：道路网、规划器、核验、发布会
│     ├─ shuru/                 输入环节（占位）
│     └─ check/                 内容文件校验（启动时和 yxz check 时运行）
├─ web/
│  ├─ index.html                入口页
│  ├─ admin.html
│  ├─ jisuan/index.html  jisuan/screen.html
│  ├─ shuchu/index.html  shuchu/screen.html
│  ├─ shuru/index.html   shuru/screen.html
│  └─ src/
│     ├─ common/                tokens.css、组件、api.ts、sse.ts、seat.ts
│     ├─ jisuan/  shuchu/  shuru/
│     └─ admin/
└─ content/
   ├─ common/                   persona.md（元小智人设，三环节共用）、seats.json、sensitive_words.txt
   ├─ jisuan/                   books.json、tags.json、prompts/、fallback/
   ├─ shuchu/                   campus/、prompts/、fallback/
   └─ shuru/
```

每个环节模块对外只暴露：

```go
type Module interface {
    Name() string                    // "jisuan"
    Routes(mux *http.ServeMux)       // 注册 /api/<name>/*
    Snapshot() ([]byte, error)       // 写状态快照
    Restore([]byte) error
    Reset()                          // 教师“重置本环节”
    Check(content fs.FS) []error     // 内容文件校验
}
```

三个模块互不依赖，只依赖 `core` 和 `llm`。

## 7. 接口约定

- 统一用 JSON；出错返回 `{"error":"给人看的中文说明","code":"seat_taken"}`，并带上合适的 HTTP 状态码。
- 学生的请求带座位令牌（Cookie `yxz_seat`）。
- 需要流式返回的接口（大模型输出）用 SSE 直接作为响应体。事件名由各模块约定，统一以 `event: done` 或 `event: error` 结束。
- SSE 推送中心：
  - `Publish(module, audience, event, data)`，其中 `audience` 可以是 `screen`、`student:all`、`student:<座位号>`、`group:<组号>`；
  - 每条事件带递增 ID，内存里保留最近 500 条，供断线重连时补齐；
  - 每 15 秒发一次注释行（心跳），防止代理断开连接。

## 8. 运行模式

在 `/admin` 里切换，也可以用环境变量 `YXZ_MODE` 设初值：

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| 实时 `live` | 调用真实模型；自动录制每次调用 | 上课 |
| 回放 `replay` | 按“场景 + 输入特征”匹配彩排时录下的真实回答；匹配不到就用兜底 | 断网 |
| 模拟 `mock` | 不联网，用规则生成回答 | 开发、演示界面 |

- 不管哪种模式，**本地计算部分（出题、偏好计算、规划器）都真实运行**。只有大模型那一步不同。
- 学生看不出处于哪种模式；只有大屏右下角有一个小圆点（绿色实时 / 黄色回放 / 灰色模拟），供教师确认。

## 9. 配置

环境变量（写在 `.env` 里，`.env` 不进仓库）：

| 变量 | 说明 | 例子 |
|---|---|---|
| `YXZ_PORT` | 监听端口 | `8080` |
| `YXZ_MODE` | 初始运行模式 | `live` |
| `YXZ_TEACHER_PIN` | 教师口令 | 课前自定 |
| `YXZ_TEXT_BASE` | 模型网关地址（OpenAI 协议） | `https://…/v1` |
| `YXZ_TEXT_KEY` | 模型密钥 | —（只放在 `.env`） |
| `YXZ_TEXT_MODEL` | 文字模型 | 开工前复测后确定 |
| `YXZ_DATA` | 数据目录 | `/data` |

其余可调参数（并发、超时、思考程度、动画时长等）放在 `content/common/config.json`，可以在 `/admin` 里临时改，改动写回 `/data/config.override.json`。

## 10. Docker

**Dockerfile（多阶段）**

```dockerfile
FROM node:22-alpine AS web
WORKDIR /src/web
COPY web/package*.json ./
RUN npm ci
COPY web/ ./
RUN npm run build                 # 输出到 /src/web/dist

FROM golang:1.25-alpine AS srv
WORKDIR /src/server
COPY server/ ./
COPY --from=web /src/web/dist ./internal/core/dist
RUN CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /yxz ./cmd/yxz

FROM alpine:3.22
RUN adduser -D yxz && apk add --no-cache tzdata ca-certificates
COPY --from=srv /yxz /app/yxz
COPY content/ /app/content/
USER yxz
ENV YXZ_PORT=8080 YXZ_DATA=/data TZ=Asia/Shanghai
EXPOSE 8080
VOLUME /data
HEALTHCHECK CMD wget -qO- http://127.0.0.1:8080/api/common/health || exit 1
ENTRYPOINT ["/app/yxz", "serve", "-content", "/app/content"]
```

**docker-compose.yml**

```yaml
services:
  yxz:
    build: .
    image: yxz-next:latest
    ports: ["8080:8080"]
    env_file: .env
    volumes:
      - ./data:/data
      # 课前要改书库或地图时，取消下一行注释，用本机目录覆盖内置内容
      # - ./content:/app/content:ro
    restart: unless-stopped
```

**课前启动**

1. `docker compose up -d`；
2. 浏览器打开 `http://localhost:8080/admin`，确认三项都是绿色：模型网关、内容校验、缓存预热；
3. 大屏打开 `/jisuan/screen`，平板扫入口页二维码。

**注意**
- Windows 防火墙第一次会询问是否允许 Docker 访问网络，要选“允许专用网络”。
- 入口页二维码用服务器的局域网 IP 生成。IP 有多个时，在 `/admin` 里选一个。
- 不能用 Docker 时，用 `make dist` 生成 Windows / macOS 单文件程序，`yxz serve` 直接运行。行为完全一样。

## 11. 日志与课后清理

- `/data/logs/yxz-日期.log`：每次模型调用的场景、耗时、输入输出 token 数、缓存命中 token 数、是否兜底。**不记录密钥。**
- `/data/replay/`：实时模式录下的调用，用于回放模式。
- `/data/uploads/`：学生上传的图片（输入环节可能会用到）。
- `yxz purge`：清除状态、上传图片和课堂记录，保留回放包；加 `-all` 连回放包一起清除。

## 12. 测试

- 每个模块都有 Go 单元测试；`make test` 全部运行。
- `yxz check`：校验全部内容文件，有错就拒绝启动，并说明错在哪个文件哪一行。
- **压测脚本** `scripts/load.ts`：模拟 30–36 台平板同时操作某个环节（模拟模式和实时模式都能跑），输出每一步的耗时分布。
