# 公共 02 · 界面风格规范

> 三个环节看起来要像**同一个产品**：同样的底色、字体、卡片、按钮、元小智形象和顶栏。区别只有一个：每个环节有自己的主色。
> 样式变量统一放在 `web/src/common/tokens.css`。组件放在 `web/src/common/components/`。各环节不得另写一套基础样式。

---

## 1. 设计基调

- **学生平板是工具**：干净、好点、字大。不放剧情动画。
- **大屏是舞台**：讲解、揭晓、“AI 在计算”的动画都放在大屏。
- **“计算面板”**：只要画面在表现“元小智正在算”，三个环节都用同一种深色面板（见第 4 节）。这样学生一看到深色面板，就知道“它在计算了”。

**三环节主色**：

| 环节 | 变量 | 主色 | 浅色 | 用在 |

## 3. 字体与字号

- 字体只用系统字体，不下载网络字体（平板可能不能上外网）：
  `"PingFang SC","Hiragino Sans GB","Noto Sans CJK SC","Source Han Sans SC","Microsoft YaHei",system-ui,sans-serif`
- 数字一律 `font-variant-numeric: tabular-nums`，跳动时不左右抖。

| 用途 | 平板 | 大屏 |
|---|---|---|
| 正文 | 18px | 28px |
| 次要文字 | 15px | 22px（大屏最小字号，后排要能看清） |
| 卡片标题 | 22px | 36px |
| 页面标题 | 26px | 52px |
| 大数字 | 36px | 96px |

## 4. 布局

**平板（横屏 1280×800 为基准）**

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：元小智头像 · 环节名      [输入 ─ 计算 ─ 输出]      3 号座位 │  56px
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                         任务区                                │
│                 （各环节自己的内容）                            │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 底部操作区：主按钮放右下角                                       │  72px
└──────────────────────────────────────────────────────────────┘
```

- 有对话的环节（输出、可能还有输入）：任务区左 55%，元小智对话区右 45%。
- 竖屏时上下排列，对话区在下面。
- 可点的元素最小 48×48px，相邻按钮间距至少 12px。

**大屏（1920×1080）**

- 按 16:9 等比缩放整个舞台：内部固定按 1920×1080 布局，外面用 `transform: scale()` 适配实际分辨率。
- 顶栏和平板一样，只是更大。右下角放运行模式小圆点。
- 底部隐藏一条**教师操作条**：鼠标移到底部或按 `Space` 显示，5 秒不动自动隐藏。快捷键在第 7 节。

**顶栏的三环节指示**

```
  ● 输入  ───  ● 计算  ───  ● 输出
```

当前环节点亮为主色、略放大，另外两个是灰色。三个环节都显示这条指示，提醒学生“我们现在在三环节的哪一环”。

| `Stamp` | 盖章动画（“验收通过”“猜中啦”） | 输出、计算 |

## 6. 动效

| 级别 | 时长 | 用于 |
|---|---|---|
| 轻 | 120ms | 按下、选中 |
| 中 | 240ms | 卡片出现、面板切换 |
| 重 | 400–600ms | 揭晓、盖章 |

- 缓动统一用 `cubic-bezier(.2,.8,.2,1)`。
- **平板只动 `transform` 和 `opacity`**。不用 `filter: blur`、`box-shadow` 动画、大面积渐变动画，同一时间最多 12 个元素在动。
- 平板上的“思考”效果靠排版节奏（一行一行出现、数字跳动、进度条），不靠粒子特效。粒子、扫描、热度图这类大量元素的画面只放在大屏，用 Canvas 画。
- **低性能模式**：在 `/admin` 里打开，或者平板首次打开时测到帧率低于 40，就自动给 `<html>` 加 `.lowfx`。此后：
  - 所有过渡缩短到 0 或 120ms；
  - 打字机效果改成整行出现；
  - 关闭闪烁边框。
- 遵守 `prefers-reduced-motion`。

## 7. 大屏教师快捷键（三个环节统一）

| 键 | 作用 |
|---|---|
| `Space` | 显示 / 隐藏操作条 |
| `→` / `←` | 下一步 / 上一步（环节内的分镜） |
| `P` | 暂停 / 继续动画 |
| `R` | 重播当前动画 |
| `1`–`9`、`0` | 快速选平板（投屏回放用，按两位数时连续按） |
| `F` | 全屏 |
| `Esc` | 回到本环节总览 |

## 8. 文案语气

- 元小智说话：第一人称，像一位亲切的学长、学姐，句子短，六年级学生能看懂。
- 界面文字：动词开头，例如“选这本”“再看一遍”“告诉元小智”。
- 不出现技术词，例如“token”“模型”“API”“缓存”。大屏讲解页可以出现“数据”“算法”“计算”，用来对应教学目标。

## 9. “再试一次”（三个环节都要有）

让学生亲手体验“再来一次，结果会不会不一样”。这是理解 AI 的关键：输入变了，结果会变；输入不变，结果也可能变。

**统一的样子**
- 位置：结果区域的右下角，和其他结果操作排在一起；次要按钮样式（白底、主色描边），带一个循环箭头图标。
- 文字：一律是“再试一次”。
- 点击后先出一个确认气泡，说明这次会怎么重来，避免误点。
- 有次数上限时，按钮旁显示“还能试 2 次”；用完后按钮变灰，提示“去看看大屏吧”。
- 新结果出来后，结果上方出现“第 1 次 / 第 2 次 / …”切换标签，可以来回对比；默认停在最新一次。
- 大屏能看到每台平板试了几次，教师可以挑出“两次结果不一样”的平板投屏讨论。

**各环节的含义**

| 环节 | “再试一次”做什么 | 输入变不变 | 想让学生体会到 |
|---|---|---|---|
| 计算 `/jisuan` | 重新选 5 轮书，再分析、再推荐（每人最多 3 次） | 变：新的选择数据 | 数据变了，计算结果就变了 |
| 输出 `/shuchu` | 用**完全相同的输入**再生成一张路线图，作为新的一版（每组最多 5 版） | 不变 | 同样的输入，AI 的输出也可能不一样（概率性） |
| 输入 `/shuru` | 把最后一个问题原样再问一次，得到一个新回答，可以左右切换（每个问题最多 3 次） | 不变 | 同一句话，AI 的回答可以不同；想要更好的回答，要改进提问 |

“再试一次”和“改一改再提交”是两件事：前者不改输入，后者改输入。输出环节和输入环节两者都有，计算环节的“再试一次”本身就是重新输入。
