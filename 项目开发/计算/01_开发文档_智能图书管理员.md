## 0. 一页看懂

- **元小智是学校的智能图书管理员。** 学生连续选 5 轮书，每轮从 5 本里选 1 本最想读的。
- 选完以后，元小智把学生的 5 次选择**倒带回放**，一轮一轮地提取出阅读偏好。然后扫描整个书库（约 300 本），像 AI 模型的思考链一样一步步推理。最后推荐 **3 本“你可能感兴趣的书”**，标出感兴趣程度（例如 92%、85%、71%），从高到低排列。
- **全部是真算**：
  - 每轮出哪 5 本书，由服务器根据前几轮的选择实时计算（元小智会“出题试探”）；
  - 偏好画像、书库打分、候选筛选，由本地算法真实计算；
  - 最后选哪 3 本、感兴趣程度、推荐理由、思考链，由大模型根据这位学生的真实数据推理生成。
- **省钱但不露馅**：所有学生共用同一套推荐提示词和书库索引，放在提示词的固定开头，命中模型的上下文缓存。每个学生的数据放在后面，所以每个人拿到的推荐都是真正针对自己的。
- **大屏**：显示全班进度和全班阅读口味；教师可以挑一台平板，把它的整个分析过程在大屏上放大重播。

**对应的教学目标**：计算 = 数据（你的 5 次选择）+ 算法（找规律、打分、筛选）+ 算力（几秒钟比对上万次）。感兴趣程度是“猜”出来的概率，不是 100%。

## 2. 学生端（平板）

### 2.1 页面流程

```
S0 选座位 → S1 开场 → S2 选书（第 1–5 轮）→ S3 分析动画 → S4 推荐结果 → S5 再想想（可选，1 次）→ S6 完成
                                                                          ↑                  │
                                                                          └─── 再试一次 ─────┘（重新选 5 轮）
```

- 每台平板就是一位“读者”。两位同学商量着选。
- 可选配置 `readers_per_seat: 2`：一位同学做完后点“换同桌来”，再走一遍。适合时间充裕的课，大屏可以对比“同一台平板，两个人的推荐为什么不一样”。默认 1。
- 刷新页面会回到原来的步骤，已选的不会丢。

### 2.2 S1 开场

- 元小智头像 + 一句话：“我是智能图书管理员元小智。接下来给你看 5 组书，每组选一本你**最想读**的。选完后，我来猜猜你会喜欢什么书。”
- 下方小字：“共 5 轮 · 大约 2 分钟”。按钮“开始”。

### 2.3 S2 选书

```
┌───────────────────────────────────────────────────────────────┐
│ 顶栏                                                          │
│ 第 3 / 5 轮   ■ ■ □ □ □   （已选的书缩成小书脊放在格子里）        │
├───────────────────────────────────────────────────────────────┤
│ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐                  │
│ │ 封面 │ │ 封面 │ │ 封面 │ │ 封面 │ │ 封面 │                   │
│ │ 书名 │ │ 书名 │ │ 书名 │ │ 书名 │ │ 书名 │                   │
│ │ 作者 │ │ 作者 │ │ 作者 │ │ 作者 │ │ 作者 │                   │
│ │ #标签 │ │ #标签 │ │ #标签 │ │ #标签 │ │ #标签 │                   │
│ │ 一句话 │ │ 一句话 │ │ 一句话 │ │ 一句话 │ │ 一句话 │                   │
│ │[看简介]│ │[看简介]│ │[看简介]│ │[看简介]│ │[看简介]│                   │
│ │[选这本]│ │[选这本]│ │[选这本]│ │[选这本]│ │[选这本]│                   │
│ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘                  │
└───────────────────────────────────────────────────────────────┘
```

- **封面**：不用真实封面图片（版权和流量都有问题）。用 CSS 生成：
  - 底色和花纹取自这本书的大类（`04` 第 3 节）；
  - 竖排书名；
  - 大类小图标（内联 SVG）。
  每本书看起来都不一样，但一个书架上的书风格统一。
- **卡片内容**：书名、作者、2 个标签（题材 1 + 风格 1）、一句话吸引语（≤18 字）。
- **看简介**：卡片原地向上展开，显示 60–100 字简介，再点收起。这个操作会被记录下来（“看过简介”是数据之一）。
- **选这本**：卡片抬起，飞进顶部的进度格，变成一根小书脊。0.6 秒后出现下一轮。选定后不能改。
- 每轮的 5 本书由服务器根据前几轮的选择生成（`02` 第 2 节），在本轮进入时向服务器要。
- 轮与轮之间，元小智头像旁边闪过一句短话，例如“记下了”“嗯……”“有意思”，从一个小句库里随机取。**不透露任何分析结果**，悬念留到 S3。

**记录的数据**（每轮）：
- 展示的 5 本书和它们在屏幕上的位置；
- 选了哪本；
- 用时（从 5 本书出现到点“选这本”，毫秒）；
- 看过哪几本的简介、先后顺序；
- 每本书的“出题目的”：试探喜好、对照、探索（服务器记录，学生看不到）。

### 2.4 S3 分析动画

选完第 5 本后立即进入，同时服务器开始计算和调用模型。分镜见 [03_思考动画脚本](03_思考动画脚本.md)。平板版是**精简版**：

| 段落 | 平板上的样子 | 时长 |
|---|---|---|
| ① 倒带回溯 | 顶部 5 根书脊从第 5 轮倒回第 1 轮。每倒到一轮，这一轮的 5 本书以小卡片重现：选中的那本亮起，没选的变灰；选中那本的标签“飞”进右边的“阅读画像”，画像里的标签条随之变长 | 约 8 秒 |
| ② 扫描书库 | 一排排小书脊（只画 120 根，代表整个书库），一条光带扫过；计数器“已比对 301 本 × 32 个标签”跳动 | 约 3 秒 |
| ③ 思考链 | 元小智的思考一行一行出现（来自模型的真实输出） | 跟随模型输出，最少 6 秒 |
| ④ 揭晓 | 3 本书依次翻面出现，感兴趣程度的进度条从 0 涨到对应数值 | 约 3 秒 |

- 平板上只用 CSS 的 transform 和 opacity，书脊用普通 div。大屏版才用 Canvas 画完整书库。
- 学生可以点右上角“跳过动画”，但这个按钮在动画开始 5 秒后才出现。

### 2.5 S4 推荐结果

```
元小智猜你是：🔖 “好奇的冒险家”
你喜欢：冒险 ██████████  动物 ██████  幽默 ████

┌────────────────────────────────────────────────────────────┐
│ ① 《书名》  作者            感兴趣程度 92%  ███████████████░  │
│    推荐理由：你第 2 轮和第 4 轮都选了冒险故事，这本……           │
│    [想读] [不想读]                                          │
├────────────────────────────────────────────────────────────┤
│ ② 《书名》 …… 85%                                          │
├────────────────────────────────────────────────────────────┤
│ ③ 《书名》 …… 71%                                          │
└────────────────────────────────────────────────────────────┘
[再看一遍分析]   元小智猜得准吗？ ☆☆☆☆☆   [再想想]   [再试一次]
```

- 理由里提到的书名、轮次都来自这位学生的真实记录。系统会校验（`02` 第 7 节），对不上的理由会被丢弃。
- “再看一遍分析”重播 S3（不再调用模型）。
- 星级评分（1–5）发到大屏，用于 V3 汇总。

### 2.6 S5 再想想（可选，限 1 次）

- 学生给 3 本书分别点“想读 / 不想读”。还可以在输入框补一句话，打字或者用输入法的语音输入都行，例如“我不喜欢太长的书”。
- 点“再想想”：
  - 本地先更新偏好：不想读的书，它的标签降权；补充的话里能识别的标签和篇幅词，作为额外信号；
  - 再调用模型。这次请求接在同一段对话后面，前面的全部内容都成为缓存前缀；
  - 动画是短版（约 8 秒）：画像里的标签条重新伸缩，“不想读”的书被划掉，再揭晓新的 3 本。
- 新推荐不会重复已推荐过的书。
- 元小智会说明它改了什么，例如：“你说不喜欢太长的书，我把厚书都往后排了。”

### 2.6b 再试一次

结果页右下角固定有“再试一次”按钮（公共组件 `RetryButton`，见 `公共/02`）。

- 点击后弹出确认：“重新选 5 轮书，看看元小智这次会怎么猜？”
- 确认后开始新的一次（`Attempt`）：
  - 重新走 S2 选书 → S3 分析 → S4 结果；
  - 出题时尽量避开这位读者前几次看过的书，书不够时才允许重复。
- 结果页顶部出现“第 1 次 / 第 2 次 / …”切换标签，下面有一行对比，例如：“第 1 次你是‘好奇的冒险家’，这次是‘快乐的动物朋友’”。这一行让学生体会到：**输入的数据变了，计算的结果就变了**。
- 每位读者最多 3 次（可配置 `max_attempts`）。用完后按钮变灰，提示“去看看大屏吧”。
- 大屏 V1 的格子上显示这台平板试了几次；V2 投屏回放可以选择看第几次。
- 每次都是完整的一次分析：模型调用和超时兜底规则都一样。

### 2.7 S6 完成

“谢谢你！我会继续学习你的口味。”平板转为“请看大屏”，等待教师操作。

## 3. 大屏（`/jisuan/screen`）

| 视图 | 内容 | 进入方式 |
|---|---|---|
| **V0 书库墙** | Canvas 画出整个书库：300 多根书脊排成书架，按大类分色，缓缓“呼吸”；标题“元小智的书库：301 本书 · 32 种标签” | 默认 |
| **V1 全班进度** | 5×5 宫格，每格是一台平板。格里有 5 个小格，每选一轮亮一格；分析中的格子外圈转动；完成后显示第一推荐书的小封面。右边是“全班阅读口味”气泡图：全班已选书的标签按次数变大，实时更新。顶部计数器：全班已做出 n 次选择；元小智已比对 m 次 | `→` 或教师操作条 |
| **V2 投屏回放** | 选中一台平板，把它的完整分析过程放大重播，是大屏完整版动画（`03`），带“草稿纸”小窗，显示模型推理过程的原文。左上角显示“3 号平板的分析过程” | 在 V1 点格子，或按数字键 |
| **V3 全班汇总** | ① 平均星级和分布；② 感兴趣程度的分布（大多在 60–95%，没有 100%）；③ 全班被推荐最多的 5 本书；④ 三张小结卡：数据（全班 125 次选择）、算法（标签打分 → 筛选 → 推理）、算力（共比对 xx 万次，用时 xx 秒） | `→` |

- V1 的气泡图和计数器只用真实数据。
- V2 播放的是服务器保存的这台平板的**分析轨迹**（第 4 节）。模型的输出是当时录下来的，不会重新调用。
- 教师操作条上的按钮：开始本环节（同时预热缓存）、暂停学生操作、选平板、思考程度（快速 / 深度，只影响之后的请求）、显示 / 隐藏草稿纸、重置本环节。

## 4. 数据与状态

```go
type Session struct {            // 一台平板上的一位读者
    Seat       int
    Reader     int               // 1 或 2（readers_per_seat=2 时）
    Stage      string            // intro | picking | analyzing | result | again | done
    Attempt    int               // 当前是第几次（再试一次 +1）；下面的 Rounds…Stars 都是当前这一次的
    History    []AttemptRecord   // 之前几次的 Rounds、Trace、Result、Stars（再试一次时归档）
    Rounds     []Round           // 最多 5 个
    Trace      *Trace            // 第一次分析的完整轨迹
    Result     *Result
    Feedback   *Feedback
    Again      *Result           // 再想想的结果
    AgainTrace *Trace
    Stars      int
}

type Round struct {
    N        int
    Shown    []Slot              // 5 本
    Chosen   string              // 书 id
    Ms       int                 // 用时
    Opened   []string            // 看过简介的书，按先后
}

type Slot struct {
    BookID  string
    Purpose string               // anchor | exploit | contrast | explore | wildcard
    Note    string               // 给倒带动画用的一句说明，例如“对照：冒险 + 搞笑 vs 冒险 + 紧张”
}

type Trace struct {              // 本地计算的全部中间结果，前端动画只读这里的数字
    PerRound   []RoundDelta      // 每轮让哪些标签加分、减分，以及原因（选中 / 没选 / 很快选定 / 犹豫）
    Profile    Profile           // 最终画像：标签权重、体裁权重、篇幅倾向
    Scores     []float32         // 书库每本书的得分，按书库顺序（大屏热度图用）
    Funnel     []FunnelStep      // 301 → 276 → 40 → 12 → 3，每层的数量和一句说明
    Candidates []Candidate       // 12 本候选：id、本地得分、本地感兴趣程度、命中标签
    Ops        int64             // 比对次数（书数 × 标签维度 × 轮次等，按实际循环计数）
    ComputeMs  float64           // 本地计算用时
    LLM        LLMTrace          // 思考链各行、推理原文（大屏用）、用时、token 数、是否兜底
}

type Result struct {
    Persona string               // “好奇的冒险家”
    TopTags []string
    Picks   []Pick               // 3 本，按感兴趣程度从高到低
}
type Pick struct {
    BookID   string
    Interest int                 // 50–97
    Reason   string
    Evidence []int               // 依据的轮次
}
```

- 状态快照：`/data/state/jisuan.json`。
- 课后 `yxz purge` 清除。

## 5. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/jisuan/start` | 开始（或继续）。返回当前 `Stage` 和已完成的轮次 |
| GET | `/api/jisuan/round` | 取当前这一轮的 5 本书。同一轮重复请求返回同样的 5 本 |
| POST | `/api/jisuan/pick` | `{round, book_id, ms, opened:[...]}`。返回 `{next: "round"\|"analyze"}` |
| POST | `/api/jisuan/analyze` | 响应体是 SSE 流，事件见下表。重复调用时，如果已有结果，直接重放轨迹 |
| POST | `/api/jisuan/stars` | `{stars}` |
| POST | `/api/jisuan/again` | `{likes:{id:true/false}, text}`，SSE 流，事件同 analyze |
| POST | `/api/jisuan/retry` | 再试一次：归档当前这一次，开始新的一次。超过 `max_attempts` 返回 `{"error":"已经试了 3 次啦","code":"max_attempts"}` |
| GET | `/api/jisuan/books?ids=` | 取书的展示信息（封面参数、书名、作者、标签、吸引语、简介） |
| GET | `/api/jisuan/screen/state` | 大屏：全部平板的进度、口味统计（教师口令） |
| GET | `/api/jisuan/screen/trace?seat=&reader=` | 大屏：某位读者的完整轨迹，用于 V2（教师口令） |
| POST | `/api/jisuan/screen/control` | 大屏：`{action: start\|pause\|resume\|reset\|effort, …}`（教师口令） |

**`/analyze` 的 SSE 事件**

| 事件 | 时机 | 数据 |
|---|---|---|
| `trace` | 立即（本地计算 < 50ms） | `Trace` 中除 `LLM` 以外的全部内容 |
| `thought` | 模型每输出一行思考 | `{i, text}` |
| `persona` | 模型输出画像行 | `{name, tags}` |
| `pick` | 模型每输出一本推荐（校验通过后） | `Pick` |
| `draft` | 模型的推理原文片段（**只推给大屏**，平板的流里没有） | `{text}` |
| `final` | 全部完成 | `Result` + `{fallback: bool}`（`fallback` 只有大屏能看到） |
| `done` / `error` | 结束 | — |

前端按事件**排进动画队列**，按动画节奏播放，不是收到就立刻显示（`03` 第 4 节）。

**大屏 SSE 推送**（`/events/jisuan?role=screen`）：`seat_progress`、`taste_update`（口味统计增量）、`analysis_done`、`stars`。

## 6. 并发与时间

- 本地计算全部在内存里完成，每次 < 50ms。
- 模型调用：25 台平板大约在 1 分钟内先后选完，同时进行的调用不超过 10 个。前缀命中缓存时，推荐场景预计 6–15 秒。
- 动画的前两段（倒带 + 扫描）约 11 秒，只用本地数据，正好盖住模型的排队和首字等待。
- 模型 25 秒内没有出第一行思考：整次用本地兜底结果；35 秒内没有完成：用本地兜底结果补齐剩余部分（已经显示的思考行保留），学生看不出区别。

## 7. 隐私与内容安全

- 不收集姓名，只有座位号。
- 学生补充的那句话先过本地敏感词表，再发给模型；包含个人信息（电话、住址等正则）时，提示“不用告诉元小智这些哦”，不发送。
- 推荐只能从书库中选，书库本身经过人工审核（`04` 第 6 节）。

## 8. 验收

1. 25 台平板同时走完 5 轮：每轮换书 < 300ms；分析从第 5 次选择到揭晓第 1 本：平均 ≤ 25 秒，最长 ≤ 40 秒（实时模式）。
2. 同一位读者两次进入，同一轮的 5 本书相同；5 轮共 25 本书不重复。
3. 推荐的 3 本：不在已展示的 25 本中；感兴趣程度从高到低；理由引用的书名和轮次与记录一致。
4. 用 `yxz check recommend` 模拟 200 位读者（`02` 第 9 节），各项指标达标。
5. 大屏 V2 回放与平板上看到的内容一致。
6. 断网后切到回放 / 模拟模式，流程照常走完。
7. 旧款平板上，选书和分析动画的帧率不低于 30。
8. `/admin` 能看到推荐场景的缓存命中率。第 2 个请求开始，命中率 ≥ 80%（网关支持时）。
