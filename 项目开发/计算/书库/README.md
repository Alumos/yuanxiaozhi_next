## 1. 文件

| 文件 | 用途 | 能不能手改 |
|---|---|---|
| `草稿/01_冒险探险.txt` … `12_诗词散文.txt` | **原始数据**，一行一本书，按大类分文件 | 能，改书都改这里 |
| `tags.json` | 大类（含封面颜色、花纹、图标）、题材、风格、体裁、来源代码 | 能，改了要重新生成 |
| `build_books.py` | 把草稿整理成正式文件，并做自检 | — |
| `books.json` | **系统读取的正式书库** | 不要手改，由脚本生成 |
| `books_review.csv` | 给老师审核用的表格（Excel 可直接打开），最后一列“审核意见”留空 | 审核时填 |
| `books_index.txt` | 推荐提示词里的“书库索引”（固定前缀），约 1.8 万字 | 不要手改 |
| `check_report.md` | 自检报告：各大类、标签、体裁的数量，对照题能不能出 | 不要手改 |
| `ids.json` | 书名 + 作者 → 编号。编号一旦分配就不再变，新加的书接着往后编 | 不要手改 |

**存储形式**：用 JSON 文件，不用数据库。

- 三百多本书只有约 220 KB。服务器启动时一次性读进内存，再建好按标签、按大类的索引，给全库打分只要几毫秒。
- 上课时书库只读不写，用不上数据库。
- JSON 可以直接打开看、对比改了什么，审核方便，也能直接打包进程序和 Docker 镜像。

正式开发时，把 `books.json`、`tags.json` 复制到 `app/content/jisuan/`。

**改书的流程**：编辑 `草稿/*.txt`，然后在本目录运行：

```bash
python3 build_books.py
```

有错误时脚本会指出文件和行号，并以非 0 状态退出。

**草稿格式**：每行 13 列，用 `|` 分隔。

```
书名|作者|中/外|题材（、分隔）|风格（、分隔）|体裁|篇幅|年级段|摸底书1/0|系列|来源代码|一句话|简介
```

来源代码：

| 代码 | 来源 | 口碑分 `q` |
|---|---|---|
| `M` | 教育部《中小学生阅读指导目录（2020 年版）》 | 1.0 |
| `K` | 统编语文教材“快乐读书吧” | 0.9 |
| `A` | 重要儿童文学或图画书奖项获奖作品 / 获奖作家作品 | 0.8 |

## 3. 这一版是怎么来的

- 书目、分类和简介都是根据已有的知识整理的。原因：
  - 教育部 2020 年目录的官方 PDF 链接已失效；
  - 媒体转载的书目是图片，读不出文字；
  - 用户确认不必继续搜索。
- 来源标注：
  - 能确认的才标 `M` 或 `K`。`K` 按统编教材“快乐读书吧”一至六年级的推荐书目标注；
  - 获奖作品标 `A`；
  - 其余标 `C`，表示“经典推荐，待核”。
  因此 `M` 只有 19 本，实际在教育部目录里的书应该更多，审核时可以补标。
- 和规范的差别：
  - 规范建议 400 本左右。这一版 301 本，已经满足出题和推荐的最低需要；
  - 篇幅里“长”只有 10%，是有意的：小学生更容易对短一点的书感兴趣。

**② 适龄性**：标 `6-7` 的书偏难，例如：

- 《记忆传授人》《超新星纪元》《钢铁是怎样炼成的》《老人与海》；
- 《呼兰河传》《湘行散记》《瓦尔登湖》等散文。

请判断是否适合六年级。不合适就删掉，或者把年级段改为 `7-7`（出题时就不会出现）。

**③ 标签**：标签决定推荐效果，请抽查标签是否贴切。例如：

- 《格列佛游记》算“冒险”还是“魔法奇幻”；
- 《苏东坡传》带“搞笑”风格是否合适。

**④ 学校图书馆**：如果能拿到馆藏目录，在 `books_review.csv` 里注明哪些书馆里有、放在哪个书架。之后我把它们填进 `in_library` 和 `shelf` 字段，推荐卡上就能显示“去图书馆 × 楼 × 类书架借”。
