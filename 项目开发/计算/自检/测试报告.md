# 计算环节 · 推荐自检报告（2026-11-07）

> 测试对象：书库 v0.1（301 本）+ 推荐算法原型（`rec.py`）+ 课堂网关上的模型 `YM ·DeepSeek-V4.1`。
> 脚本：`sim.py`（本地模拟，不调用模型）、`llm_test.py`（调用模型）。密钥只从环境变量读取，没有写进任何文件。

---

## 一句话结论

**默认调用大模型（`low` 思考），超时走本地算法。** 本地算法和模型的推荐准确度差不多，所以超时兜底时学生分辨不出来。

- 本地算法 1 秒内出结果，不花钱，断网也能用。
- 推荐准确度和模型差不多（平均百分位：本地 0.91–0.92，模型 0.90–0.94），学生分辨不出来。
- 课堂网关上的模型能跑通，但不稳定：会丢系统提示词，缓存也命中不了。只适合在网络好的时候锦上添花。

## 1. 本地算法：200 位模拟读者

**方法**
- 每位模拟读者随机设定一种隐藏口味：喜欢 2–3 个题材和 1 种风格，不喜欢 1 个题材，偏好某种体裁和篇幅。
- 读者按口味加一点随机性选书，完成 5 轮后由算法推荐 3 本。
- 检查推荐的书在读者真实口味里排第几：百分位越接近 1 越好；0.8 表示排在前 20%。
- “选得认真”“选得随意”用选择的随机程度区分（温度 0.3 / 0.5）。

| 指标 | 认真选：出题试探 | 认真选：随机给书 | 随意选：出题试探 | 随意选：随机给书 |
|---|---|---|---|---|
| 推荐的书排进读者口味前 20% | **71%** | 67% | 62% | 58% |
| 3 本平均排进前 20% 的读者 | **70%** | 65% | 61% | 49% |
| 推荐书的平均百分位 | **0.83** | 0.80 | 0.79 | 0.76 |
| 画像前 2 个题材猜中读者喜欢的题材 | **80%** | 66% | 73% | 57% |
| 被推荐过的不同书占书库 | 78% | 78% | 72% | 82% |
| 单本书最高占比 | 1.3% | 1.7% | 1.5% | 2.2% |
| 第 3 轮结束时见过的大类（最少） | 10 个 | 5 个 | 10 个 | 5 个 |

**解读**
- “出题试探”比随机给书准，猜中读者喜欢的题材提高了 14–16 个百分点，这个数字可以直接用于课堂讲解。
- 推荐分布很散：没有“人人都推荐那几本”的情况。
- 准确度的上限主要受**信息量**限制：只有 5 次选择。实验对比：
  - 8 轮能提高约 4 个百分点；
  - 学生选得越认真越准。
  - 换更复杂的画像算法（选择模型）、“覆盖优先”的出题方式，提高都不到 2 个百分点，所以不采用。
- 最终采用：**原出题策略 + 按标签稀有度加权的画像**。“成长”“友谊”这类几乎每本书都有的标签权重降低，喜欢的题材更容易被认出来。每轮加减分的数字可以直接用于倒带动画。
- 原定目标“85% 排进前 20%”在 5 轮的信息量下达不到，改为：**认真选时 ≥ 65%，平均百分位 ≥ 0.8**。

## 2. 大模型：课堂网关实测

| 测试 | 结果 |
|---|---|
| 思考程度参数 | `reasoning_effort` 有效：`low` / `medium` 会输出推理过程；`thinking: disabled` 可以关掉 |
| 网关额外注入 | 每个请求都被网关加了约 350 token 的系统提示词 |
| **丢系统提示词** | 用 `YM ·DeepSeek-V4.1`、提示词放在 system 时，10 次里有 4 次输入只剩约 2600 token，规则和书库都丢了，模型答成了 Markdown 长文。**改为放进用户消息后，没再出现** |
| **上下文缓存** | 基本不命中：命中率 2–7%，偶尔命中几十到三千 token。网关可能在多个上游之间轮换。**结论：不依赖缓存** |
| `medium` 思考 | 平均 20 秒，最慢 79 秒；有一次推理写了近 9000 字，用完了输出额度，没给出推荐 |
| **`low` 思考 + 不带书库索引（最终方案）** | 6 次全部格式正确，0 次失败；平均 14 秒，最长 24 秒；每次输入约 5200 token（原来约 1.8 万） |
| 推荐质量（`low`） | 模型推荐的平均百分位 0.90，本地前 3 为 0.92，基本一样 |
| 思考链（`low`） | 37 行全部通过校验；83% 的推荐理由引用的轮次和推荐书确实有相同标签 |

**`low` 档的一次真实输出**（模拟读者口味：机器人科技、成长、知识多）：

```
想|证据|第5轮你犹豫14.3秒选《小灵通漫游未来》，科幻你很喜欢。
想|证据|第4轮7.1秒就拿下《哆啦A梦》，机器人科技最合你口味。
想|证据|第3轮你选《哈克贝利·费恩历险记》，冒险小说你也读得进。

同一位读者，本地模板输出的思考链是：

```
想|证据|第4轮和第5轮，你都选了机器人科技的书。
想|证据|第4轮你7秒就选了《哆啦A梦》，是你选得最快的一次。

模型写得更生动，本地模板更规整。两者引用的都是这位学生的真实数据。

## 3. 由此定下的方案

| 项 | 决定 |
|---|---|
| 默认推荐方式 | **大模型**（`low` 思考）：从本地算出的 12 本候选里选 3 本，写思考链和理由（2026-11-07 用户决定） |
| 超时兜底 | 25 秒没出第一行思考 → 整次用本地结果；35 秒没完成 → 缺的部分用本地结果补齐；校验不通过的行同样用本地补。`/admin` 可以关掉模型，全部走本地 |
| 提示词位置 | 整段放在**用户消息**里，不用 system（这个网关会丢 system） |
| 书库索引 | **不放进提示词**，只发 12 本候选的简介；“发现候选之外的书”这一功能取消 |
| 缓存 | 不依赖。前缀仍然保持固定，网关以后支持缓存时自然会生效 |
| 思考程度 | 最低一档 `low`；如果还嫌慢，可以改成 `off`（关闭思考，约 5 秒） |
| 动画 | 不变。倒带、扫描、漏斗用本地数据（约 13 秒，正好盖住模型的等待）；思考链播放模型的输出，兜底时播放本地模板 |
| 再试一次 | 结果页有“再试一次”，重新选 5 轮，每人最多 3 次 |

## 4. 下一步要改的

- 本地模板再多准备几种句式，避免全班同学的思考链读起来一模一样。
- 本地画像称号在少数情况下会生成“好奇的榜样追随者”这种别扭的组合，需要补一张称号白名单。
- 正式开发时把 `rec.py` 用 Go 重写，逻辑不变。
