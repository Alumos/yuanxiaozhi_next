# 计算 02 · 推荐算法与提示词

> 推荐分四步。前三步是本地算法（Go，毫秒级，结果可复现），第四步由大模型推理。每一步的中间数字都写进 `Trace`，动画只播放这些真实数字。

> **2026-11-07 实测后的调整**（详见 [自检/测试报告](自检/测试报告.md)）：
> - **默认调用大模型**：思考程度 `low`。超时就走本地算法：
>   - 发出请求后 **25 秒**还没出第一行思考，整次改用本地结果；
>   - **35 秒**还没完成，缺的部分用本地结果补齐。
>   本地结果和模型结果格式完全一样，学生看不出区别。`/admin` 可以关掉模型，全部走本地。
> - 提示词放在用户消息里（课堂网关会丢 system）。
> - 书库索引不进提示词，只发 12 本候选的简介；取消“发现候选之外的书”。
> - 不依赖上下文缓存（网关上基本不命中）。
> - 结果页有“**再试一次**”按钮（见 `01` 第 2.6b 节）。
> 下文中与此冲突的地方，以本说明为准。

```
① 出题（每轮实时）→ ② 偏好画像 → ③ 书库打分 + 候选筛选 → ④ 大模型推理：选 3 本、定感兴趣程度、写理由和思考链
```

标签体系、书目字段见 [04_图书数据采集规范](04_图书数据采集规范.md)。下面用到的记号：

- `topic(b)`：书 b 的题材标签，2–4 个，来自 24 个题材；
- `tone(b)`：风格标签，1–2 个，来自 8 种风格；
- `form(b)`：体裁，6 种之一；
- `len(b)`：篇幅，短 / 中 / 长，对应 −1 / 0 / +1；
- `cat(b)`：大类，12 个之一。

---

## 1. 为什么不直接让大模型推荐

1. **省时省钱**：300 本书的打分由本地算法几毫秒算完。大模型只需要在 12 本候选里做精细判断。
2. **看得见**：本地计算的每一步都有数字，可以拿来做动画，而且是真的。
3. **稳**：候选都来自书库，模型不会编出不存在的书。模型超时了，本地结果可以直接顶上。
4. **教学上说得清**：元小智 = 大模型 + 计算工具 + 学校数据（和输出环节的规划器同一个说法）。

## 2. 出题策略（每轮 5 本书）

元小智不是随机给书，而是像做实验一样“出题试探”。每一本书都有一个**出题目的**（`Slot.Purpose`），倒带动画里会讲出来。

| 轮次 | 5 本书的构成 | 目的 |
|---|---|---|
| 第 1 轮 | 5 本 `anchor`，来自 5 个不同大类；至少 1 本不是小说 | 先大范围摸底 |
| 第 2 轮 | 1 本 `exploit`（和第 1 轮选中的书有 ≥2 个相同标签）+ 1 本 `contrast`（同一大类、不同风格）+ 3 本 `explore`（还没出现过的大类） | 验证第一印象，继续摸底 |
| 第 3 轮 | 2 本 `exploit`（当前得分最高）+ 1 本 `contrast`（和其中一本题材相同、风格不同）+ 2 本 `explore` | 找出喜欢的风格 |
| 第 4 轮 | 2 本 `exploit` + 1 本 `contrast`（题材相同、体裁不同，例如漫画和小说）+ 1 本 `explore` + 1 本 `wildcard`（书库里口碑最好的书中随机一本） | 找出喜欢的体裁，留一点意外 |
| 第 5 轮 | 2 本属于当前第一假设（得分最高的题材组合）+ 2 本属于第二假设 + 1 本篇幅对照 | 二选一，定胜负 |

规则：
- 5 轮共 25 本书**不重复**；同一作者、同一系列最多出现 2 本。
- 第 3 轮结束时，至少出现过 9 个大类。
- 5 本书在屏幕上的位置用“座位号 + 轮次”做种子打乱，避免出题目的和位置有关。
- 同一位读者重复请求同一轮，返回相同的 5 本（结果存进 `Round.Shown`）。
- 每本书的 `Slot.Note` 用模板生成，例如：
  - `exploit`：“上一轮你选了冒险书，这本也是冒险。”
  - `contrast`：“对照题：都是动物故事，一本搞笑、一本感人。”
  - `explore`：“探索：你还没见过科普书。”
  - `wildcard`：“彩蛋：书库里很受欢迎的一本。”

## 3. 偏好画像

对每一轮 r（展示 `S_r`，选中 `c_r`，用时 `ms_r`，看过简介 `O_r`），先算**果断系数**：

```
conf_r = 1.20   若 ms_r < 4 秒（很果断）
       = 1.00   若 4–12 秒
       = 0.85   若 > 12 秒（犹豫）
```

然后累加权重 `w`（题材、风格共用一张表，体裁单独一张表 `f`，篇幅单独累计 `L`）：

| 信号 | 权重变化 | 倒带动画里的说法 |
|---|---|---|
| 选中的书，每个题材标签 | `+1.0 × conf_r` | “选中 +1” |
| 选中的书，每个风格标签 | `+0.8 × conf_r` | “选中 +0.8” |
| 没选的书，它有而选中书没有的标签 | `−0.25` | “没选 −0.25” |
| 没选但看过简介的书，同上 | `−0.12`（看过说明有点兴趣，扣得少） | “看了没选 −0.12” |
| 对照题：选中的那本独有的风格或体裁 | 额外 `+0.5`；另一本独有的 `−0.3` | “对照题：你选了搞笑的那本” |
| 体裁 | 选中 `f[form] += conf_r`；没选的体裁 `−0.2` | — |
| 篇幅 | `L += len(c_r)`，最后取平均 `L̄` | “你偏爱短一点的书” |

**归一化**：`p[t] = w[t] / max|w|`，范围 −1 到 1；体裁同理得到 `pf`。

**画像输出**（`Trace.Profile`）：
- 前 5 个正权重标签；
- 前 2 个负权重标签（“可能不感兴趣”）；
- 最喜欢的体裁、篇幅倾向；
- 每轮的变化 `PerRound`（倒带动画逐轮播放）。

## 4. 书库打分与候选筛选

**打分**：书库里除已展示的 25 本外，每本书都打分：

```
s(b) = ( Σ_{t∈topic(b)} p[t] + 0.7 × Σ_{t∈tone(b)} p[t] ) / sqrt(|topic(b)| + |tone(b)|)
     + 0.35 × pf[form(b)]
     − 0.15 × |len(b) − L̄|
     + 0.03 × q(b)            // q：口碑分 0–1（来自推荐书目的权威程度，见 04）
```

- `Trace.Ops` 按循环实际执行的乘加次数计数。大屏上显示“比对了 9 632 次”这类数字，就是这么来的。
- 全部打分按书库顺序存进 `Trace.Scores`，大屏热度图用。

**漏斗**（`Trace.Funnel`，每层都是真实数量）：

| 层 | 规则 | 例 |
|---|---|---|
| 书库 | 全部 | 301 |
| 去掉已看过 | 去掉 5 轮展示过的 25 本 | 276 |
| 有兴趣的 | `s(b) > 0` | 143 |
| 初选 | 得分前 40 | 40 |
| 候选 | 多样化挑选 12 本（下面） | 12 |
| 推荐 | 大模型选 3 本 | 3 |

**多样化挑选（MMR）**：从前 40 本里逐本挑 12 本，每次选使下式最大的书：

```
0.7 × s(b) − 0.3 × max_{c∈已选} sim(b, c)        sim = 两本书标签集合的 Jaccard 相似度
```

再加约束：同一作者或系列最多 1 本；12 本至少覆盖 3 个大类。

**本地感兴趣程度**（只作为参考和兜底）：

```
z = (s(b) − s_40) / (s_1 − s_40)        s_1 / s_40：初选第 1 名 / 第 40 名的分数
interest_local = round(58 + 36 × z)      → 58–94
```

## 5. 大模型这一步做什么

输入：这位学生的 5 轮记录（含用时、看过简介）、本地画像、12 本候选（含简介和本地感兴趣程度）。

输出：
1. **思考链** 3–6 行，每行标一个类型：`证据` / `推断` / `排除` / `发现` / `结论`；
2. **阅读画像**：一个称号（≤8 字，例如“好奇的冒险家”）+ 3 个标签；
3. **3 本推荐**：书的 id、感兴趣程度、理由（≤45 字，要引用学生的真实选择）、依据的轮次。

模型可以做本地算法做不到的判断：
- 读简介理解内容，比如同样是“动物”，一本是科普、一本是童话；
- 综合犹豫、看简介这些细节；
- 发现候选之外更合适的书。**最多 1 本**可以不在候选里，但必须在书库索引里、不在已展示的 25 本中，并且思考链里要有一行 `发现`。

最终的感兴趣程度：

```
interest = clamp(模型给的值, interest_local(b) − 8, interest_local(b) + 8)，再限制在 50–97
```

3 本按感兴趣程度从高到低严格递减；相同时后面的减 1。**永远不出现 100%**，这是教学点：AI 是“猜”，有把握的程度不同。

## 6. 提示词

### 6.1 固定前缀（system，全班完全相同，命中缓存）

由三部分按顺序拼接：`common/persona.md` + `jisuan/prompts/recommend_rules.md` + 书库索引。

**`recommend_rules.md`（正文草稿）**

```
你现在是学校的智能图书管理员“元小智”，正在给一位六年级学生推荐课外书。

【你会收到】
1. 学生 5 轮选书记录：每轮展示的 5 本书、选了哪本、用了几秒、看过哪些书的简介、每本书的出题目的。
2. 计算工具算出的阅读画像：标签权重（正数=喜欢，负数=不太感兴趣）、喜欢的体裁、篇幅倾向。
3. 计算工具选出的 12 本候选书：编号、书名、标签、简介、参考感兴趣程度。

【你要做】
从候选书中选出 3 本这位学生最可能想读的书。最多可以有 1 本不在候选里，但必须在下面的书库索引里，且不在学生已经看过的 25 本里。

【规则】
- 只依据给你的数据推理，不要猜测学生的个人信息。
- 思考要具体：引用第几轮、哪本书、用了几秒、看没看简介。不要说空话。
- 感兴趣程度是 50 到 97 之间的整数，3 本从高到低。参考值只是参考，你可以上下调整，但要有依据。
- 推荐理由写给学生看：用“你”称呼，不超过 45 个字，至少提到一次学生真实选过的书或做过的事。
- 不要提“分数”“权重”“算法”“候选”“编号”这些词；不要推荐学生已经看过的 25 本书。
- 语气亲切，像高年级的学长学姐。

【输出格式】只输出下面这些行，每行一条，不要输出别的内容：
想|证据|……（引用具体的轮次和书）
想|推断|……
想|排除|……
想|发现|……（只有推荐了候选之外的书时才写）
想|结论|……
画像|称号|标签1,标签2,标签3
荐|书的编号|感兴趣程度|推荐理由|依据的轮次（用逗号分隔）
荐|……
荐|……
完

“想”写 3 到 6 行，每行不超过 40 个字。

【示例】
（两组完整的输入和输出示例，覆盖：①偏好明确；②偏好分散、有犹豫。示例里的书来自书库，但不与真实课堂常见组合重复。）

【书库索引】每行：编号|书名|作者|大类|题材标签;风格标签|体裁|篇幅|一句话
b0001|……
……
```

**书库索引**由程序从 `books.json` 生成：

- 按 `id` 排序，字段顺序固定；
- 每行大约 40–50 token，301 本约 1.8 万字、1.4 万 token 左右；
- 启动时计算整个前缀的哈希写进日志；书库改动后哈希会变，需要重新预热。

## 7. 输出解析与校验

按行解析，边收边推：每收到完整的一行，校验通过就推一个 SSE 事件。

| 行 | 校验 | 不通过怎么办 |
|---|---|---|
| `想` | 类型合法；≤40 字；`《》` 里的书名必须是已展示的 25 本或推荐的书；“第 n 轮”的 n 在 1–5 之间，并且提到的书确实出现在那一轮 | 丢弃这一行 |
| `画像` | 称号 ≤8 字；标签在词表里 | 用本地规则生成（第 10 节） |
| `荐` | id 存在；不在已展示的 25 本中；3 本互不相同；最多 1 本不在候选里；感兴趣程度是整数 | 丢弃这一本，用本地候选按顺序补齐 |
| 理由 | ≤45 字；提到的书名必须是已展示的书；依据轮次里选中的书和推荐书至少有 1 个相同标签 | 不合格的轮次去掉；没有合格依据时，用模板理由 |

- 思考行少于 3 条时，用本地模板补齐。
- 收到 `完` 或流结束，就发 `final` 事件。
- 校验结果写进日志，用于统计模型的遵守率（`公共/03` V4）。

## 8. 开销估算

假设一个班 25 位读者，每人分析 1 次、“再想想” 1 次，共 50 次调用。

| 方案 | 每次输入 | 全班合计 |
|---|---|---|
| **A（默认）：书库索引放在前缀里** | 前缀约 2 万（缓存）+ 变化约 1.8 千 | 未缓存约 11 万 + 命中缓存约 98 万 |
| A，但网关不支持缓存 | 约 2.2 万 | 约 110 万，全部按原价 |
| B：前缀只有规则和示例（约 3 千），书库不进前缀 | 3 千（缓存）+ 1.8 千 | 未缓存约 9 万 + 命中缓存约 15 万 |

- 输出每次约 350 token；开 `low` 思考时，另有几百个推理 token。
- **选 A 的理由**：模型真的“看过”整个书库，可以做“发现”（推荐候选之外的书），大屏上“元小智浏览了整个书库”也是真的。缓存命中后，A 的额外开销很小。
- 如果开工前验证 V1 发现网关**不透传缓存**，A 每次要多算 2 万 token，首字也会慢几秒。这时切到 B：`config.json` 里设 `catalog_in_prefix: false`，同时关闭“发现”。
- 具体费用按网关价格表计算。不论 A 还是 B，全班总量都在百万 token 级别以内。

## 9. 离线自检：`yxz check recommend`

用**模拟读者**检验算法，不调用模型，几秒钟跑完：

1. 随机生成 200 位读者。每人有一个隐藏口味：
   - 喜欢 2–3 个题材、1 种风格；
   - 不喜欢 1 个题材；
   - 一种体裁偏好、一个篇幅偏好。
2. 每轮按隐藏口味算出 5 本书的效用，加随机噪声，用 softmax 选一本；用时随效用差距变化（差距大 → 快）。
3. 走完 5 轮后，用本地算法推荐 3 本，统计：

| 指标 | 要求 |
|---|---|
| 推荐的 3 本，按隐藏口味的效用排在未展示书的前 20% | ≥ 85% 的读者 |
| 画像前 2 个标签里，至少有 1 个是隐藏喜欢的题材 | ≥ 90% |
| 被推荐过的不同书目，占书库的比例 | ≥ 35% |
| 单本书被推荐的最高占比 | ≤ 5% |
| 第 3 轮结束时出现过的大类数 | 每位读者 ≥ 9 |
| 和“随机出题”相比，第 1 项指标 | 至少高 10 个百分点 |

- 最后一项用来证明“出题试探”真的有用。数字可以写进教师讲解：“元小智出的题，比随便给书猜得更准。”
- 带模型的检查：`yxz check recommend -live 20`，用 20 位模拟读者真实调用模型，统计格式正确率、校验通过率、平均耗时和缓存命中率。

## 10. 本地兜底

模型超时、出错或处于模拟模式时，用本地结果生成**同样格式**的输出：

- **推荐**：候选的前 3 本，用 `interest_local`。
- **画像称号**：`风格形容词[最高风格] + 的 + 题材称呼[最高题材]`。

  | 风格 | 形容词 | | 题材 | 称呼 |
  |---|---|---|---|---|
  | 搞笑 | 快乐的 | | 冒险 | 冒险家 |
  | 紧张刺激 | 勇敢的 | | 动物 | 动物朋友 |
  | 温暖感人 | 温柔的 | | 科学 | 小科学家 |
  | 烧脑 | 爱动脑的 | | 侦探推理 | 小侦探 |
