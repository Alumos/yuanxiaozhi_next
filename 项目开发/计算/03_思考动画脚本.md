# 计算 03 · 思考动画脚本

> 目标：让学生和评委真切地感到“元小智在分析很多数据、一步步推理”。
> 底线：**动画里的每个数字、每个标签、每一行思考都来自这位学生的真实计算轨迹（`Trace`）和模型的真实输出**，动画只决定“什么时候、怎样出现”。
> 平板版是精简版，只用 CSS；大屏版是完整版，书库和热度图用 Canvas。两版用同一份轨迹数据、同一个时间轴，只是画法不同。

---

## 1. 总时间轴

```
0s        8s         11s   13s                   约 22s      25s
│①倒带回溯 │②扫描书库  │③漏斗 │④思考链（跟随模型输出）│⑤揭晓 3 本 │
│本地数据   │本地数据   │本地  │模型数据               │模型数据   │
```

- ①②③ 只用本地数据（`trace` 事件，< 50ms 就到），开场就能播。这 13 秒正好盖住模型的排队和首字等待。
- ④⑤ 用模型的数据（`thought` / `persona` / `pick` 事件）。
- 整个画面都放在 `CalcPanel`（深色计算面板，见 `公共/02`）里。面板左上角是元小智头像（思考状态，外圈转动），右上角是“计算中”闪烁点和计时器。

## 2. 分镜

### ① 倒带回溯（约 8 秒，每轮 1.6 秒）

**画面**
- 面板顶部是一条“记忆带”：5 格，放着学生选过的 5 本书脊。
- 出现 `◀◀ 倒带` 字样，旁边的时间码倒着走（“第 5 轮 00:38 → 第 1 轮 00:00”，用的是学生实际的选书时间）。
- 背景有轻微的横向扫描线（CSS 重复渐变，只做位移动画），表现“回放录像”的感觉。

**每一轮（从第 5 轮倒回第 1 轮）**
1. 记忆带上这一格亮起，这一轮的 5 本书以小卡片从右侧滑入，排成一排（0.3 秒）。
2. 选中的那本放大、描紫边；没选的 4 本变灰、缩小（0.3 秒）。
3. 卡片下方弹出这一轮的“观察”，最多 2 条，来自 `PerRound`：
   - “3.1 秒 · 很果断 ×1.2”
   - “对照题：你选了搞笑的那本”
   - “看了《…》的简介，但没选”
4. 标签从卡片上“飞”向右侧的**阅读画像**（0.5 秒）：
   - 选中书的标签带 `+1.0`，飞过去后对应的标签条变长；
   - 没选书的标签带 `−0.25`，以小号灰字飞过去，标签条略微缩短。
5. 这一轮的卡片向左淡出，进入下一轮（倒回更早的一轮）。

**阅读画像**（面板右侧，整个动画期间一直在）：
- 横向标签条，按当前权重排序。排序变化时，条目平滑换位（只用 `transform`）。
- 底部是“体裁”和“篇幅”两个小指针。

**倒带结束**：画像定格，标题从“正在提取……”变为“你的阅读画像（初步）”。

### ② 扫描书库（约 3 秒）

**大屏**：Canvas 画出整个书库（例如 301 根书脊，按大类分色）。一条紫色光带从左扫到右，扫过的书脊按 `Trace.Scores` 变色：
- 得分高 → 橙色并略微升高；
- 得分接近 0 → 灰色；
- 负分 → 暗下去。
扫完后整面书库就是一张热度图。

**平板**：只画 120 根代表性的书脊（普通 div），光带扫过时按分数切换 class。

**计数器**（`RollingNumber`）同时跳动：
- “已比对 301 本”；
- “× 32 个标签”；
- “= 9 632 次比较”（`Trace.Ops`）；
- “用时 0.004 秒”（`Trace.ComputeMs`）。

### ③ 漏斗（约 2 秒）

`Funnel` 组件逐层收窄，每层数字跳出，旁边一句说明：

```
301  书库里的全部书
276  去掉你已经看过的 25 本
143  和你的口味有关的
 40  最接近你口味的
 12  挑出 12 本风格不一样的，交给元小智细读
```

12 本候选书以小封面排成一排，“交给元小智细读”。

### ④ 思考链（跟随模型输出，最少 6 秒）

**画面**：`ThinkingStream`。思考一行一行出现，每行前面有一个类型图标：

| 类型 | 图标 | 颜色 |
|---|---|---|
| 证据 | 放大镜 | 青色 |
| 推断 | 灯泡 | 紫色 |
| 排除 | 划线 | 灰色 |
| 发现 | 星星 | 橙色 |
| 结论 | 对勾 | 绿色 |

- 每行用打字机效果出现，速度每秒 12–16 字（低性能模式下整行出现）。
- 行里提到的书名，会让候选书或记忆带里对应的封面闪一下，用来表现“它在看证据”。
- 模型输出“画像”行时，右侧画像的标题变成称号（例如“好奇的冒险家”），并盖一个小印章。
- 行与行至少间隔 0.6 秒。模型输出得快，就排队等着；输出得慢，就执行下面的“等待策略”。

**大屏额外的“草稿纸”小窗**（右下角，可以在教师操作条里关闭）：
- 实时显示模型推理原文（`draft` 事件）。
- 小字号，飞快地向上滚动，半透明，标题是“元小智的草稿纸”。
- 这是真实的推理过程，用来给评委看“它真的在想”。不要求学生读懂。
- 思考程度为 `off` 时没有推理原文，小窗显示“快速模式：直接作答”。

### ⑤ 揭晓（约 3 秒）

- 3 张书卡依次从候选排中“抽出”，翻面到正面（第 3 名先出、第 1 名最后出，制造悬念）。
- 每张卡出现时：
  - 感兴趣程度的进度条从 0 涨到对应数值，数字跟着跳；
  - 理由一行淡入；
  - 依据的轮次在记忆带上亮一下。
- 第 1 名出现时，盖一个“为你推荐”的印章（`Stamp`，只播一次）。
- 结束后面板淡出，切到 S4 结果页（大屏 V2 停在揭晓画面）。

## 3. “再想想”短版（约 8 秒）

1. 3 本旧推荐排成一排，“不想读”的被划掉、淡出（1 秒）。
2. 画像的标签条按新的权重重新伸缩，变化大的标签旁边显示 `−0.6` / `+0.5`（2 秒）。
3. 漏斗快速重走一遍，只显示最后两层：12 本新候选 → 3 本（1 秒）。
4. 思考链，第一行是“我根据你的反馈改了……”（跟随模型输出）。
5. 揭晓新的 3 本（3 秒）。

## 4. 播放调度

前端有一个**动画调度器**：数据事件进入队列，调度器按分镜节奏取出播放。

```
收到的数据：trace ─────────────── thought thought ── persona ─ pick pick pick ─ final
播放的节奏：[①倒带 8s][②扫描 3s][③漏斗 2s][④思考链 ……][⑤揭晓 3s]
```

**规则**
1. 每段有最短时长。数据早到也要按节奏播，不跳过。
2. ①②③ 不依赖模型，永远按固定时长播完。
3. 到第 ④ 段时，如果还没收到任何 `thought`，启动**等待策略**：
   - **细读候选**：12 本候选书逐本放大，高亮它和学生口味相同的标签，旁边显示本地得分。每本 1.2 秒，循环。这些数据也是真的（候选的命中标签和得分）。
   - 每循环一遍，头像旁换一句短话：“这本也不错……”“再比一比……”。
   - 从发出请求算起满 25 秒仍没有第一行思考，就调用本地兜底，直接用兜底结果继续播放 ④⑤。
4. 第 ⑤ 段要等 3 本 `pick` 都到齐（或者 `final` 到达）才开始。
5. 播放进度存在内存里。刷新页面后，如果分析已完成，就直接显示 S4 结果，提供“再看一遍”。
6. “再看一遍”和大屏 V2 都从服务器取完整轨迹，按同一个调度器离线重播（思考链按录下的节奏重放），不再调用模型。

## 6. 性能要求

| 端 | 要求 |
|---|---|
| 平板 | 同时动的元素 ≤ 12 个；只用 `transform` / `opacity`；书脊 ≤ 120 根；动画全程帧率 ≥ 30（旧款平板实测） |
| 大屏 | Canvas 每帧只重画变化的区域；书库 301 根书脊一次画完，扫描时按列增量更新；帧率 ≥ 50 |
| 低性能模式 | 打字机效果改成整行出现；倒带每轮缩短到 1 秒；扫描线和光带只保留颜色变化 |

## 7. 教学讲解对照（教师用）

| 画面 | 可以这样讲 |
|---|---|
| 倒带回溯 | “元小智把你的每次选择都当成数据，连你犹豫了多久都记下来了。” |
| 对照题 | “它不是随便给书的，它在出题试探你。” |
| 书库热度图 + 比对次数 | “几秒钟比较了一万多次，这就是计算机的算力。” |
| 漏斗 | “算法一层层筛选，最后只留下 12 本交给它仔细想。” |
| 思考链 / 草稿纸 | “它在推理：根据证据得出结论，就像你们做阅读题一样。” |
| 感兴趣程度 | “为什么没有 100%？因为这是它猜的，猜就有可能不准。” |
| 再想想 | “你告诉它不准，它就会调整，这就是 AI 在学习。” |
