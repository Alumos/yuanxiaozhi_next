# 输入 00 · 需求占位（`/shuru`，待定）

> 状态：**待定**。活动一的交互形式还没定，本文件只记录已经确定的约束、开发时可以直接使用的公共能力，以及需要决定的问题。需求定下来后，在本目录新增 `01_开发文档_xxx.md`。

---

## 1. 已确定的

- 活动一侧重**输入**：元小智和学生对话。
- 路径 `/shuru/`（学生平板）和 `/shuru/screen`（大屏），和另外两个环节在同一个 Docker 项目、同一个端口里。
- 界面风格和另外两个环节一致，主色为输入蓝 `#2a73c9`（`公共/02`）。
- **不做语音识别**。语音用平板输入法自带的语音输入转文字；系统收到的就是文字。
- 不收集学生真实姓名。
- **要有“再试一次”按钮**：把最后一个问题原样再问一次，得到新回答，可以左右切换对比（公共组件 `RetryButton`，规则见 `公共/02` 第 9 节）。

## 2. 开发前就能用的公共能力

| 能力 | 组件 / 模块 | 说明 |
|---|---|---|
| 元小智对话区 | `ChatPanel` | 文字气泡、图片气泡、“正在思考”气泡；流式显示回答 |
| 输入法语音提示 | `ChatPanel` 的 🎤 按钮 | 不录音。点了以后聚焦输入框，提示“点键盘上的话筒，说完再点发送”，并把这条消息标为“语音” |
| 拍照 / 选图 | `ChatPanel` 的 📷 按钮 | `<input type="file" accept="image/*" capture>`；客户端压缩到长边 1024；识图时再缩到 800 |
| 看图放大 | `ZoomViewer` | 同输出环节 |
| 输入形式统计 | 每条消息带 `kind: text\|voice\|image` | 可以在大屏上统计“全班用了几种输入方式” |
| 三环节小标签 | 元小智回答下方 | 输入了什么（字数、图片张数）→ 计算用了几秒 → 输出了什么 |
| 个人信息检测 | `core/privacy.go` | 正则识别手机号、住址、身份证号等，发送前提醒 |
| 模型网关 | `llm` | 文字模型、识图模型；固定前缀缓存；兜底 / 回放 / 模拟 |
| 大屏 | `CalcPanel`、`ScreenControls` 等 | 同另外两个环节 |

## 3. 需要决定的问题

1. 活动一的大任务是什么？上一版教学设计（上一级 `01_教学设计.md`）里的“求助信封”是否保留？那一版是 A 拍照题、B 输入法朗诵古诗、C 含虚构个人信息的借书问题。
2. 以小组还是以平板为单位？
3. 是否需要识图模型？如果需要，开工前要复测速度（旧平台实测识图比文字慢很多）。
4. 大屏上展示什么？例如“你发了什么 / 元小智收到了什么”的输入回放墙。
5. 活动时长：上一版是 7 分钟。
