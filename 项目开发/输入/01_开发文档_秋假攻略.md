# 输入 01 · 开发文档：秋假攻略（`/shuru`）

> 2026-11-08 实现并实测。取代 `00_待定_需求占位.md` 中的待定项。

## 1. 活动

学生把秋假出游的想法“输入”给元小智：选项（想看的风景、想玩什么、和谁去、几天、怎么去、节奏；出发地固定为学校所在地苏州）+ 一句补充（输入框在右侧对话区底部）（可以打字，也可以点平板输入法的话筒说）。元小智推荐 3 个中国境内的地点，并给第一个写分天攻略。

**教学重点：输入。**
- 平板上，发送前实时显示“元小智将会收到：……”；发送后显示“元小智收到的输入 · N 条信息”，等待时逐条点亮，表示“它在读你的每一条信息”。
- 每个推荐都标出“对上了：××”，让学生看到输出和哪条输入对应。
- 改输入再发 → 攻略变了；**再试一次**（输入一个字不改）→ 也可能不同。版本标签可以来回对比。每台平板最多 6 份。
- 大屏“输入墙”：每台平板给了几条信息、写没写补充、用没用语音；“大家想要的”统计；点一台看“输入 → 输出”并排。

## 2. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/shuru/meta` | 选项（`content/shuru/chips.json`） |
| GET | `/api/shuru/state` | 本平板的全部攻略 |
| POST | `/api/shuru/ask` | `{prefs, text, voice, retry, focus}`，响应是流：`input` → `place`×3 → `title` → `day`… → `bring` → `tip` → `final` → `done` |
| GET | `/api/shuru/screen/state`、`/screen/seat?seat=` | 大屏（教师口令） |
| POST | `/api/shuru/screen/control` | `look` / `unlook` / `reset` |

模型输出按行协议（`content/shuru/prompts/guide_rules.md`），边收边解析边推送。思考程度 `off`。
个人信息（电话、住址）和敏感词在发送前拦下。

## 3. 兜底

- 30 秒还没有出第一个推荐 → 改用本地结果（`content/shuru/places.json` 20 个地点，按偏好打分生成同格式攻略）；45 秒总超时。
- 网关返回 503 / 429 / “200 但一个字没有” → 自动重试 1 次。
- 网关出错时，并发上限最多每 10 秒减半一次，最低 8，之后每 3 秒恢复 2。
- 实时模式下成功的攻略自动录制，断网时切“回放”可用。

## 4. 25 台平板并发实测（课堂网关 `YM ·DeepSeek-V4.1`，2026-11-08）

| 测试 | 结果 |
|---|---|
| 直连网关，25 个同时（网关状态好时） | 25/25 成功，首个推荐平均 8.2 秒、最慢 14.3 秒；整份平均 10.3 秒、最慢 16.6 秒；格式 25/25 正确 |
| 经本系统，25 台同一秒提交（修复限流后，网关状态好时） | 25/25 拿到攻略，24 份来自模型、1 份本地兜底；首个推荐平均 11.4 秒；整份中位 12.7 秒 |
| 经本系统，25 台在 40 秒内陆续提交（更接近课堂） | 25/25 来自模型，0 份兜底；整份中位 8.6 秒，最慢 31 秒 |
| 连续压测约 300 次之后 | 网关开始大量 503 / 无响应：直连 25 个同时只成功 16 个；本系统 25 台仍然全部拿到完整攻略，但约一半是本地兜底，最慢约 35 秒 |

| 经本系统，**30 台**在 40 秒内陆续提交 | 30/30 拿到攻略，27 份来自模型、3 份本地兜底；整份中位 7.8 秒，最慢 34 秒 |

**结论**
- 不会卡死：任何情况下 25 台都能在 35 秒内拿到完整攻略，平板不会一直转圈。
- 速度和“是不是模型写的”取决于网关当时的状态。网关正常时，学生陆续提交，大多数 10 秒左右拿到攻略。
- 这个网关对同一个密钥的并发承受能力会波动，短时间请求太多会被限流。**课前不要反复压测**；上课前用 1–2 台平板试一下即可。
- `/admin` 里的“同时请求模型的上限”默认 12：网关稳定时可调到 25；报错多时调小，多出来的请求在本机排队。
- 断网或网关不可用时，在 `/admin` 切到“回放”，用录好的真实攻略；或切“模拟”，用本地攻略。
